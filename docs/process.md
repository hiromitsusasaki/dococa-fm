# どう作ったか — Claude Code と Claude の使い方

Dococa FM は 2026-11-03 から 11-07 の 5 日間で、ひとりの人間と Claude Code で作りました。この文書は「Claude を何に使い、何に使わなかったか」と、その証拠を置くためのものです。

## 1. 製品の中の Claude（聴く人から見える部分）

| 係 | 何をするか | 何をしないか | どう確かめるか |
|---|---|---|---|
| 判定係 | お便りを 6 つの理由（誹謗、宣伝、個人情報、作品と無関係、公序良俗、作品をけなすのが主体）で通すか断るか決める | 悲しいお便り・そっけないお便りは断らない | 1 ツールだけの tool use。失敗は fail closed（断る側に倒す） |
| 翻訳係 | お便りを一度だけ訳して保存する | 原文を書き換えない。URL・連絡先・長さが怪しい訳は捨てて原文を出す | 原文と訳の両方を検証コードが見る |
| 台本係 | お便り 1 通ごとに DJ の「紹介」と「一言」を書く | お便りを言い換えない、時事を言わない、数（件数・順位・一致率）で測らない、再生を促さない、差出人を紹介で名指ししない | `verify.ts` が決定的に検査し、落ちたら書き直し、それでも落ちたら定型の手渡しだけで読む |
| 選曲係（Claude ではない） | 聴く人の好みからの遠さで次のお便りを選ぶ | 遠さの値を画面・応答・ログ・DJ の言葉に出さない（出るのは近く・隣・遠くの札だけ） | Workers AI の埋め込み（`bge-m3`）とコサイン距離。Claude は呼ばない |
| 読み上げ（Claude ではない） | Gemini-TTS が行ごとに読む | — | 指示文が読み上げられた clip は長さで見抜いて作り直す |

Claude が触れるのは「お便りの本文と作品の題名・作者」だけです。Worker の中の Claude は 1 つのツールしか持たず、ネット・ファイル・DB に触れません。見つけた声の収集バッチだけ Agent SDK を使い、hook でツール呼び出しをすべて拒否して「選ぶ」以外をさせていません。

**AI がしないこと**（README にも同じ表があります）: お便りは原文のまま。出典の無い「見つけた声」を作らない。DJ は時事を言わない。数字で人や作品を測らない。検証に落ちた番組は保存も再生もされません。

## 2. 開発の中の Claude Code（作る側）

### 役割分担

| 役 | モデル | 仕事 |
|---|---|---|
| 指示役（このセッション） | Claude Opus 5.5 / Fable 5.1 | 設計書と計画を書く。タスクごとに実装者とレビュアーを起こし、指摘を裁く。本人に判断を仰ぐ点を決める |
| 実装者 | Claude Sonnet 5.5（設計判断を含むタスクは Opus） | 1 タスクずつ、テストを先に書いて実装し、ブラウザで画面を確かめ、報告書を書く |
| レビュアー | Claude Opus 5.5 | 仕様との一致・セキュリティ・品質を読み取りだけで見て、Critical / Important / Minor を付ける |
| 再レビュー | Sonnet（Critical が絡むときは Opus） | 修正が指摘に答えたかだけを見る |
| 第二の目 | Codex（OpenAI、read-only） | 各 Phase の最後に全体の diff を読む。Claude 側とは独立に指摘を出す |
| 本人 | 人 | 設計書の承認、本番を聴いての差し戻し、push とデプロイ、公開の判断 |

進め方は `superpowers:subagent-driven-development`（タスクごとに新しい実装者とレビュアーを起こし、台帳に裁定を残す）です。実装者は自分でサブエージェントを起こしません。レビューは必ず指示役が別のモデルで起こします。

### 裁定の例（台帳から。レビュアーの指摘を「断った」例も含む）

- **API の制約で計画を変えた**: 「Claude Sonnet 5.5 は forced `tool_choice` と temperature の指定に 400 を返す。裁定: 実装者の逸脱を受け入れる — `tool_choice: auto` + 厳密なツール + 指示文 + コードでの検証」（Phase 1）
- **機械で保証できない指摘を、保証できる形に言い直した**: Codex「言い換えは機械的に検出できない（Blocker）」→ 裁定: 「機械で保証するのは、お便りの行が原文そのままであることと、DJ の行がお便りを引用しないこと（10 文字の窓）。言い換えは指示文と eval で扱う。README にそう書く」（Phase 1）
- **指摘を断った**: Codex「本文の前後の空白を除いているのは verbatim に反する」→ 裁定: 「空白の除去は入力の正規化で、内容ではない。誤解を招くテスト名を直し、README に『前後の空白だけ除く』と書く」（Phase 1）
- **安全のために GET を消した**: 「`GET /episodes/new` は状態を変える GET で、リンクの先読みが番組を作り枠を使う。裁定: 計画を直し、`POST /start` が作って 303 する」（Phase 1）
- **仕様の読み方を決めた**: 「自分のお便りに付いた『私も』と一言を読む回は『お便りの無い作品』ではない。他人の文を原文で読むのだから。追記 K が禁じるのは誰も書いていない作品であって、反応ではない」（Phase 3）
- **費用の指摘を断った**: Codex「同じ作品の埋め込みが並行して 2 回課金される」→ 裁定: 「1 回 1 万分の 1 円未満で結果も同じ。受け入れて SECURITY.md に書く」（Phase 4）
- **本番を聴いて設計を直した**: 挨拶の clip に読み上げられた指示文が乗り「Dococa FM の紹介」に聞こえた → 本番の clip 364 本を測り（日本語 1 字 0.20 秒、英語 0.093 秒）、見張りの閾値を実測から決め直し、お便り指定のときは挨拶を飛ばす（Phase 5）

台帳の全文は公開リポには置いていません（レビューの経過は private の作業場にあります）。設計書の追記 A〜O（`docs/superpowers/specs/2026-11-03-dococa-fm-design.md`）が、本人の差し戻しで何が変わったかの記録です。

## 3. 使い分けの理由

- **Sonnet で実装、Opus でレビュー**: 同じモデルに書かせて読ませると、同じ思い込みを通す。別のモデルと別の文脈で読ませるのが安い保険。
- **Codex を最後に**: Claude 系だけで閉じると見落としが揃う。Phase 5 では Codex が「既存の Google 利用者に公開 URL が付かない」「通報の説明が実装と違う」を見つけ、Claude 側が「英語の回で日本語の行が必ず失敗する」「失敗し続ける行への無限課金」を見つけた。重なりは少ない。
- **hooks**: Worker には置かない（Agent SDK は Node 専用）。収集バッチでは PreToolUse hook で道具を全部拒否し、Claude に「選ぶ」しかさせない。
- **Skills / サブエージェント**: 計画の作成（`writing-plans`）、実行（`subagent-driven-development`）、仕上げ（`finishing-a-development-branch`）、ブラウザ確認（`playwright-cli`）、API の確認（`claude-api`）。
- **MCP は作って消した**: Phase 1 で「同じ回を Claude のアプリから取り出す」MCP を作ったが、聴く体験の中心ではなかったので Phase 4 で撤去した（設計書追記 L）。

## 4. 本人が直した点（本番を聴いて）

2026-11-05 夜（Phase 1 のデプロイ後）、11-06、11-07 の 3 回、本人が本番を聴いて差し戻した。主なもの: DJ は「かける」のではなく「紹介して、お便りを読む」（追記 I）、「土地」を「お住まい」に、ダイヤルはラジオの面に、1 回 1 枠でダイヤルがすぐ効くように、声の話し方を「ねっとり」から簡潔に、BGM がほぼ無音だった（Phase 1 の仮の音のまま）、挨拶に指示文が乗っていた。全部、聴かないと分からない種類の問題だった。
