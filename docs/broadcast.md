# 放送のタイミング — お便りはいつ読まれるか

Dococa FM は「ラジオ」と「お便り」の作法で動きます。本物のラジオでは、送ったお便りがその日の放送で読まれるとは限りません。この製品も、お便りが届いてから放送に乗るまでに時間差があってよい、と考えています（本人決定 2026-11-07）。

## ハッカソン期間中（いまの動き）

- お便りを送ると、サーバーがすぐに DJ の語り（紹介と一言）を書き、音声を作ります（`prepareLetter`）。
- それとは別に、15 分ごとの Cron（`prepareBatch`）が、まだ語りや音声の無いお便りを古い順に埋めます。
- だから、送ったお便りはふつう数十秒〜15 分で、ほかの人のラジオに乗ります（自分のラジオの選曲には自分のお便りは入りません。自分では、ホームのカードや共有ページから聴けます）。審査員が送ってすぐ聴けるように、期間中はこの形にしています。

## ハッカソン後（予定）

- Cron を 1 日 1 回（日本時間の深夜）にして、お便りは「翌日の放送」で読まれるようにします。送ったあとの画面の文言は「届きました。明日の放送で読まれます。」に変えます。
- 変えるのは Cron の文字列（`wrangler.jsonc` の `triggers.crons`）と、投稿直後の生成を止める 1 か所、文言だけです。費用は変わりません（作る量は同じ）。まとめて作るので、音声合成の連続呼び出しが拒否される問題が減ります。
- 例外: お便りを指定して聴くとき（ホームのカード、`/letters/:id` の直リンク、`/?letter=`）は、その場で語りと音声を作って読みます。「この一通をすぐ聴きたい」は今までどおりです。
- 既存の語りを作り直す必要はありません。Phase 3 から DJ の語りはお便りごとの単位で、作品に新しいお便りが来ても前の単位は変わりません。

## なぜそうするか

- 「送ったらすぐ鳴る」はチャットの作法で、「お便りは放送で読まれる」はラジオの作法です。後者のほうが、この製品の静かさに合っています。
- 1 日分をまとめて作ると、上限（Claude の呼び出し数、音声合成の行数）の読みが立ち、外部 API の瞬間的な拒否にも強くなります。
