# Dococa FM Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 世界のどこかの誰かが置いた「その曲・本・映画と自分」の一言を、聴く人一人のために組まれたラジオ番組にして流す Web アプリ（Dococa FM）を、11/8 20:00 までに端から端まで動く形で作る。

**Architecture:** 1 つの Cloudflare Worker に Hono を置き、ページは Hono JSX でサーバー描画、プレイヤーだけ hono/jsx/dom のクライアント部品にする。番組は「枠の決定（決定的コード）→ Claude が DJ の発話を書く（Messages API、tool use、読み取り専用の道具）→ コードがお便り原文を差し込んで台本を組む → 検証 4 項目（決定的コード）」の順で作り、同じ台本を画面・クラウド TTS・MCP の 3 つの出口から出す。

**Tech Stack:** TypeScript、hono 4.13、@cloudflare/vite-plugin 1.67、wrangler 4.156、Cloudflare D1 / R2、@anthropic-ai/sdk 1.4（Messages API）、@hono/mcp 0.3 + @modelcontextprotocol/sdk 1.32、zod 4、vitest 5 + @cloudflare/vitest-plugin 1.5、Web Speech API、Google Cloud Text-to-Speech REST（Gemini-TTS、スタイルはプロンプト指定）、Media Session API（PWA）、iTunes Search API、Spotify Web API（PKCE）、Google Books API、TMDB API、YouTube Data API v3。

**Spec:** `docs/superpowers/specs/2026-11-03-dococa-fm-design.md`

## Global Constraints

- 期限 2026-11-08 20:00。公開リポ。初 commit を期間内に。commit は `feat:` `fix:` `docs:` `test:` `chore:` の prefix + 英語要約、細かく。
- musico-web / musico-react / virtual-dj-space / digline のコード・スキーマ・文言・UI を一切持ち込まない。
- secret は Cloudflare secrets と `.dev.vars`（gitignore）。リポに入れない。鍵名は `ANTHROPIC_API_KEY` `SPOTIFY_CLIENT_ID` `GOOGLE_TTS_API_KEY` `TMDB_API_KEY` `YOUTUBE_API_KEY` `ADMIN_TOKEN` `SESSION_SECRET`。
- Hono は 4.13 系の安定版。HonoX は使わない。パッケージマネージャは pnpm。
- DJ は時事を言わない（年号・今日・ニュース・流行・季節の挨拶）。お便りは原文のまま。出典の無い「見つけた声」を作らない。ラジオネーム・土地・年以外の個人情報を出さない。「孤独の解消」「治療」を名乗らない。
- 画面の文言は日本語。辞書は `src/worker/i18n/ja.ts` に置き、`t(key)` 経由でのみ出す（英語追加に備える）。
- 見える部分のデザインは `personal-design` skill のパレットと声に従う（個人プロジェクト）。
- 数字で人や作品を測らない: 件数・ランキング・一致率を画面にも台本にも出さない。
- 1 リスナー 1 日の番組生成は `EPISODE_DAILY_LIMIT`（既定 10）まで。クラウド TTS は本人のデモ回と各リスナーの最初の 1 回だけ。
- 見つけた声は 1 件 100 字まで、投稿者名と元 URL 必須、別枠表示、削除依頼の口あり。

## Review Focus

1. 対応外・到達不能・本文の無い URL を貼ったとき: 落ちずに「作品が見つかりませんでした」と検索への導線を返す（Task 3 のテスト `resolveUrl_unsupported_returns_null`、Task 5 の `POST /letters with unresolvable url → 422`）。
2. お便り本文に HTML や `<script>`、極端に長い文が入ったとき: 画面はエスケープされ、TTS には素のテキストだけ渡り、201 字以上は 422（Task 5 `letter_body_is_escaped_in_item_page`、`letter_body_over_200_chars_rejected`）。
3. Claude が道具を呼ばない・壊れた JSON を返す・応答しないとき: 2 回まで作り直し、それでも駄目なら DJ の感想抜きで「お便りを読むだけの回」を返す（Task 8 `compose_falls_back_to_readings_only`）。
4. ブラウザで `speechSynthesis.getVoices()` が初回に空のとき: `voiceschanged` を待ってから再生し、日本語の声が無ければ既定の声で読む（Task 10 `player_waits_for_voices`）。
5. ダイヤルが 0 または 1 のとき: 「遠く」は常に 1 枠以上、「近く」が材料不足なら「遠く」で埋め、番組は必ず 5 作品以上になる（Task 7 `selectProgram_dial_extremes`）。

### Task 3: 作品の解決（URL 貼り付け、検索、プレビュー）

**Files:**

**Interfaces:**
- Produces: `type ItemDraft = Omit<Item,"id"|"createdAt">`。`resolveUrl(url: string, env: Env): Promise<ItemDraft | null>`、`searchByText(q: string, kind: ItemKind | "any", env: Env): Promise<ItemDraft[]>`（最大 5）、`resolveOrCreate(db, draft): Promise<Item>`（`externalIds` のどれかで既存があればそれを返す）。
- 決め（`url.ts`）: `parseKnownUrl(url): { provider: "spotify"|"youtube"|"apple-music"|"amazon"|"filmarks"|"letterboxd"|"netflix"|"unknown"; id?: string }`。対応: `open.spotify.com/track/:id`、`youtube.com/watch?v=` と `youtu.be/`、`music.apple.com/.../id` の `?i=`、`amazon.co.jp|com/.../dp/:asin`、`filmarks.com/movies/:id`、`letterboxd.com/film/:slug`、`netflix.com/title/:id`。
- 決め（経路）: spotify / youtube は oEmbed（認証不要、題名と作者）→ 題名で iTunes 検索してプレビューと画像を得る。apple-music は iTunes `lookup?id=`。amazon / filmarks / letterboxd / netflix / unknown は OGP（`og:title` `og:image`）→ 種別推定（amazon の `/dp/` に ISBN-10 形があれば book、filmarks / letterboxd / netflix は film、それ以外は iTunes → Google Books → TMDB の順に検索して最初に当たった種別）。
- 決め（`itunes.ts`）: `https://itunes.apple.com/search?term=&media=music&entity=song&limit=5&country=JP`。`previewUrl` `artworkUrl100`（`100x100` を `600x600` に置換）`trackViewUrl` `releaseDate` を使う。`books.ts`: Google Books `volumes?q=`（`isbn:` があれば優先）、`imageLinks.thumbnail` を https に。`tmdb.ts`: `search/movie?query=&language=ja-JP` に `Authorization: Bearer TMDB_API_KEY`、`poster_path` は `https://image.tmdb.org/t/p/w500` 前置。
- 決め: `outLinks` は取れたものだけ入れる（`spotify` `apple` `youtube` `amazon` `netflix` `filmarks` `letterboxd` `google-books` `tmdb`）。無い出口は画面で検索 URL（`https://open.spotify.com/search/<title>` 等）を組む。
