# 0016 上限とレート制限は「数えてから動く」でよい（既知の制限）

- **Status:** Accepted（既知の制限として）
- **Date:** 2026-11-04（公開前の整備）、2026-11-06（費用のかかる呼び出しごとの上限を追加）

## Context

匿名でも聴けて、お便りを送れて、裏で Claude と音声合成が動きます。暴走や悪用で費用が青天井にならない歯止めが要ります。一方で、Worker の isolate をまたぐ厳密な数え方（呼び出しの予約台帳など）を 5 日で作るのは重い。

## Decision

費用のかかる呼び出しの前に D1 の数を確かめ、上限を超えていたら呼ばない、という形にします。

| 上限 | 守るもの |
|---|---|
| 単位の 1 日の数 | 単位を作る Claude |
| 合成する行の 1 日の数 | 音声合成 |
| お便りと一言の 1 日の数（全員） | 判定と翻訳の Claude |
| 枠の 1 日の数（1 人・全体） | 番組の作成 |
| 題名検索の YouTube の 1 日の数 | YouTube の枠 |
| 1 行への合成の回数 | 指示文を読み上げてしまう行への再試行 |

- どれも `0` は停止、日は日本時間で数える。値と既定は [docs/cost.md](../cost.md) と SECURITY.md にある。
- 上限に当たったら、劣化した形で続ける。単位が無ければ定型の手渡しだけで読み、音声が無ければブラウザの声で読む。
- 毎分のレート制限は、書き込みと外部 API を呼ぶ経路に IP とリスナーごとに置く。カウンタは isolate ごとのメモリ。

## Consequences

既知の制限として SECURITY.md に書いたもの:

- 判定は原子的ではないので、同時に届いた要求で上限を数回超えることがある。超過の幅は毎分のレート制限が抑える。
- 毎分のレート制限は isolate をまたがないので、実効の上限は表より緩くなりうる。
- 全体の上限は、cookie を捨てながら使う 1 人に使い切られうる。復旧は運営者が上限を上げること。
- 判定で断ったお便りは保存しないので、お便りの上限に数えられない。

2026-11-08 の提出後に、Cloudflare 側の Rate Limiting ルール（IP ごと 10 秒に 30 回の `POST`）と WAF のマネージドルール、HTTP ライブラリからの書き込みのブロックを足しました。書き込みの経路へのチャレンジは、ブラウザの `fetch` を壊すので入れていません（SECURITY.md「Cloudflare 側の守り」）。
