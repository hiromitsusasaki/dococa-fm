# 0005 Claude は 1 ツールだけの tool use。ネット・ファイル・DB に触れない

- **Status:** Accepted
- **Date:** 2026-11-03（呼び出しの形は 2026-11-04 に確定）

## Context

台本係・判定係・翻訳係には、他人が書いたお便りを渡します。お便りの中に指示が紛れ込んでいても、Claude が外へ何かをしてしまわない作りにしたかった。また、Claude Agent SDK は Worker の中で動きません。

## Decision

Worker の中の Claude は、Messages API の tool use で呼び、渡す道具は答えを返す厳密なツール 1 つだけにします。

- 台本係は `write_unit`（紹介と一言、読み）だけを持つ。判定係・翻訳係・読みの係も、それぞれ答えを返すツール 1 つ。
- ネット・ファイル・DB に触れる道具は渡さない。書き込みも URL の生成も、道具に無いので物理的にできない。
- お便りの本文はコードが原文から差し込む。Claude の出力を本文として使わない。
- 判定が失敗したときは公開しない側に倒す（fail closed）。翻訳が失敗したときは原文を出す。

当初の設計では「お便りを ID で引く」などの読み取りの道具を渡す案でした。実装では、必要な材料を最初から渡し、道具は答えを返す 1 つだけにしました。

## Consequences

- 使ったモデルは、ツールを強制する `tool_choice` と temperature の指定に 400 を返した（2026-11-04）。計画を直し、`tool_choice: auto` + 厳密なツール + 「必ず 1 回呼ぶ」という指示文 + コードでの検証、にした。呼ばなかった・壊れた答えは書き直し、だめなら定型だけで読む。
- 厳密なスキーマでは長さの制限が落ちるため、長さはコードで確かめる。
- 見つけた声の収集バッチ（ローカル）だけは Agent SDK を使う。道具を 1 つも渡さず、さらに呼ばれたら必ず拒否する PreToolUse hook を付け、Claude には候補の ID を選ばせるだけにしている。
- 作品の読みは、お便りを一切見せない別の呼び出しで作る（[0011](0011-readings-from-work-data-and-per-unit.md)）。
