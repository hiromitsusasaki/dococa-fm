# 0011 読み（カタカナ）は作品データから、台本係の読みは単位ごと

- **Status:** Accepted
- **Date:** 2026-11-07

## Context

音声合成は固有名をよく読み間違えます。本番では「PSY」や「大船渡」が別の読みで読まれました。読みを直したい一方で、画面の表記とお便りは書いたままにしなければなりません。また、作品の読みは全員の番組で共有されるので、誰か 1 人のお便りに引っ張られた読みが全員に広がるのは避けたい。

## Decision

読みは DJ の行の音声だけに効かせ、出どころを二つに分けます。

- **作品の題名と作者の読み。** 作品のデータ（題名・作者・年・種類）だけを見せる専用の呼び出しで、作品ごとに 1 回だけ作って保存する。お便りは一切見せない。冒頭の一行（「…という曲の紹介です」）と紹介の読みに使う。かなだけの名前には呼ばない。
- **語りと手渡しの名前の読み。** 台本係が単位を書くときに、読み間違えそうな名前の読みを 8 個まで返す。その単位の語りと手渡し（送り主の名前とお住まい）にだけ当てる。
- 音声用の本文は作るときに組み立てて保存し、音声の鍵もその本文で決まる。画面と JSON には出さない。
- お便りの行には付けない。お便りは音声も原文のまま。英語の行にも付けない。

## Consequences

- 読みはモデルの自由な出力なので、全角カタカナだけ、元の表記に比べた長さの上限つき、英字・数字・漢字を含まない表記と数字だけの表記には付けない、と絞った。外れたものは捨て、単位は通す。
- 音声用の本文にも、語りと同じ検査（時事・数え上げ・再生の誘い・個人情報・引用）をかける。「名前をカタカナに置き換えただけ」でなければ落とす。
- 作品の読みは作り直しでも変わらない。間違っていたら運営者が消し、次の事前生成で聞き直す。
- 残る余地: お便りの中の指示に引っ張られた台本係が、その単位の名前に本当の読みではない短いカタカナを付けることはありうる。範囲はその単位の中だけで、受け入れた（SECURITY.md）。
