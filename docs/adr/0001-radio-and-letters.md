# 0001 ラジオとお便りという形

- **Status:** Accepted
- **Date:** 2026-11-03

## Context

作りたかったのは「自分が好きなものを好きな人が世界のどこかにいる」と感じられる場です。好みの一致で人を結ぶ製品はすでに多く、失敗の型も見えていました。一致率は浅く、非主流の好みに弱い。チャットルームは人が来なくなると死ぬ。AI が生成した MC は「機械の文章を読まされる」と嫌われる。

ブレストの途中では、小さなグループチャットの裏に AI を置く案もありました。ただ、特定の閉じた場を前提にしていて、誰でも開ける製品になりませんでした。

## Decision

器は「流れ続けるラジオ」にし、中身は人が書いた一行の「お便り」にします。

- 深夜ラジオの作法に従う。ラジオネームで書く、DJ が読む、返事は義務でない、聴くだけでいい。
- お便りは「その場で出る一行」。長文も内省も求めない。
- リスナー同士の DM・プロフィール・一致率・マッチングは作らない。反応は「私も」と一言だけで、数ではなく「どこかの誰か」として届く。
- DJ は AI だが、読まれる言葉はすべて人が書いたもの。

## Consequences

- 「AI がしないこと」（[0002](0002-verify-what-ai-must-not-do.md)）が製品の芯になった。AI の役目は、人の言葉を損なわずに運ぶことに絞られる。
- 書く人が少ないと番組が成り立たない。最初の一歩を軽くするために、URL を貼るだけで作品が立ち上がる入口と、デモ用のペルソナ（[0014](0014-demo-data-as-labeled-ai-personas.md)）を足した。
- 「いつ読まれるか」もラジオの作法で考えることになった（[0013](0013-daily-broadcast-after-hackathon.md)）。
- 2026-11-05 に、DJ は曲を「かける」のではなく「紹介してお便りを読む」と決め直した（設計書の追記 I）。この局で流れ続けるのは語りだけで、作品は画面の出口から聴きに行く。
