# 0008 単位（お便りごとの DJ の語り）と、👍 で育てる改善ループ

- **Status:** Accepted
- **Date:** 2026-11-06

## Context

Phase 1 では、聴くたびに回ごとの台本を Claude に書かせていました。費用が聴く回数に比例し、同じお便りでも聴くたびに語りが変わり、検証に落ちる機会も聴くたびにありました。語りの質を上げる手がかりも残りませんでした。

## Decision

DJ の語りを、お便り 1 通・言語ごとに 1 回だけ作る「単位」にします。

- 単位は `intro`（作品の紹介。送り主は名指ししない）と `after`（短い感想）の 2 行。手渡し「〇〇さんからのお便りです」はモデルが書かない定型。
- 単位は作ったときに検証する。通らなければ語りを使わず、定型だけで読む。
- お便りが届いたら応答のあとで作り、15 分ごとの Cron が残りを埋める。番組は単位を並べるだけ。
- 改善は本人が回す。管理画面で良い intro に 👍 を付けると、同じ言語の 👍 付き・検証済みの intro が新しい順に 5 件、次に作る単位の指示文に「良い例」として入る（intro だけで、お便りの本文は入れない）。👎 はその場で作り直し、新しい単位が検証を通ったときだけ置き換える。
- 数が多いときは採点スクリプトで Claude に 5 点満点で採点させ、低い 10 件と指示文への提案を読む。指示文の変更は本人が手で入れる。

## Consequences

- 聴くだけなら、通常は Claude 0 回。費用はお便りの数に比例する。
- 語りの方針を変えると、単位を作り直す migration が要る（冒頭の一行を足したときは全部を作り直した）。
- 同じ単位を 2 つの処理が同時に作らないよう、1 単位に作り手は 1 人にした。検証済みの単位は上書きしない。
- 作り直しも 1 日の上限に数える。
- 自動では指示文を変えない。採点の提案を採るかは人が決める。
