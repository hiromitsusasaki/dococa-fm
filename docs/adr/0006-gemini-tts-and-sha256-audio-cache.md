# 0006 Gemini-TTS と、文の SHA-256 を鍵にした音声キャッシュ

- **Status:** Accepted
- **Date:** 2026-11-03（TTS の選定）、2026-11-06（音声キャッシュ）、2026-11-07（見張りの締め直し）

## Context

DJ の声は製品の印象を決めます。ブラウザの音声は端末ごとに質がばらつきます。一方でクラウドの声は 1 行ごとにお金がかかり、聴くたびに合成すると費用が聴く回数に比例します。

## Decision

- **声は Google Cloud の Gemini-TTS。** 自然文の指示で話し方を決められ、日本語が使える。声は本人が試聴して男性の Charon に決めた（2026-11-05）。クラウドの声が使えない行は、ブラウザの音声が読む。
- **認証はサービスアカウントの署名。** Gemini-TTS は API キーでは通らなかった（2026-11-05）。Worker がサービスアカウントの鍵で JWT を署名し、アクセストークンに交換する。
- **音声は「言語 × 声 × 本文の SHA-256」を鍵に R2 に 1 回だけ作り、全員で共有する（2026-11-06）。** 同じお便りは誰の番組でも同じ音声、定型のつなぎと手渡しは一度作れば全員が使う。
- **指示文の読み上げを長さで見抜く。** 合成した MP3 の長さが、文字数から見込む長さを超えたら、指示文を読んだとみなして捨てて作り直す。

## Consequences

- 費用が「聴く回数」ではなく「お便りの数」に比例するようになった。聴くだけなら、通常は合成 0 回。
- 指示文や鍵の版を変えると、全部の音声を作り直すことになる。鍵の版は v2 → v3 → v4 と上がった。次の調整では DJ の行とお便りの行で鍵を分ける案がある（[docs/cost.md](../cost.md)）。
- 2026-11-06、本番で指示文が本文の前に読まれる問題が見つかった。日本語の指示文を命令形にし、見張りを入れた。2026-11-07、本番の clip 364 本を測り（日本語 1 字 0.20 秒、英語 0.093 秒）、閾値を「3 秒 + 日本語 0.27 秒/字、英語 0.125 秒/字」に締め直した。
- 何度作っても指示文を読む行に払い続けないよう、1 つの鍵への合成はおよそ 6 回までにした。超えた行はブラウザの声が読む。
- 40 字以下の短い行は、読みが二重になるのを避けるため 2 回合成して短いほうを使う。
- 1 日に合成する行数の上限を置いた（[0016](0016-count-then-act-limits.md)）。
