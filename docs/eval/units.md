# 単位の採点（`pnpm eval:units`）

DJ の語り（単位。お便り 1 通ぶんの intro と after）を Claude に 5 点満点で採点させ、`docs/eval/units-<日付>.md` に書きます。点数は単位を見直すためのもので、作品やお便りを測るものではありません。

## 走らせ方

```bash
read -rs PROD_ADMIN_TOKEN   # 本番のトークンをシェルに読み込む（画面にも履歴にも出ない）
ADMIN_TOKEN="$PROD_ADMIN_TOKEN" pnpm eval:units --origin https://dococafm.app --lang ja --limit 40
ADMIN_TOKEN="$PROD_ADMIN_TOKEN" pnpm eval:units --origin https://dococafm.app --lang ja --limit 40 --remake   # 2 点以下を作り直す
```

トークンは環境変数 `ADMIN_TOKEN` で渡します（`--token` も使えますが、実行中はプロセスの引数として他のユーザーから見えるので使わないでください）。シェルで指定した値は `.dev.vars` より優先されます。ローカル（`--origin` を省略）なら `.dev.vars` の `ADMIN_TOKEN` をそのまま使います。`ANTHROPIC_API_KEY` が要ります（`.dev.vars` から読みます）。モデルは `CLAUDE_MODEL`、無ければ `claude-sonnet-5-5`。単位 1 件に Claude を 1 回、提案に 1 回呼びます。`--limit` は 1〜100（既定 40）で、`/admin/units.json` のお便り ID 順の先頭から採点します。標準出力に出すのは件数だけです。

## 基準

1. 作品の具体的な一点に触れる（どの作品にも言える褒め言葉で済ませない）
2. 煽らない（大げさな形容、断定的な称賛、聴取や視聴を促す言い方をしない）
3. ネタバレしない
4. お便りの言い換えにしない（intro がお便りの中身を先取りしたり要約したりしない）
5. 手渡しに自然につながる（intro のあとに名前と土地の定型文、その後にお便りの朗読が続く）

5 = すべて満たす、1 = ほとんど満たさない。採点者はお便りの本文も読みます（4 を確かめるため）。

## レポートの読み方

- **点の分布**: 5〜1 点の件数。採点できなかった単位（ツールの答えが形に合わない、API の失敗）は全件の表で「—」になり、分布には入りません。
- **全件**: お便り ID・作品・点。ID は `/admin/units` の行と同じで、そこで 👍 や作り直しができます。
- **低い 10 件**: 点の低い順に、採点者のメモ（満たしていない基準の番号と理由）。メモにお便りの文面が 8 文字以上続けて入っていたら、そのメモは「（お便りの文面を含むため省略）」に置き換えます。レポートは commit するので、お便りの文面と DJ の台本そのものは書き出しません。
- **指示文への提案**: 3 点以下のメモから Claude が出した、指示文に足す・直す一文。自動では反映しません。本人が読んで採るものに印（`[x]`）を付け、`src/worker/program/unit.ts` の指示文に手で入れます。

## 輪の回し方

1. `/admin/units` で良い intro に 👍 を付ける（その言語の新しい 5 件が、次に作る単位の指示文に良い例として入る）。
2. `pnpm eval:units` で採点し、低いものを `--remake` か画面の 👎 で作り直す。
3. 提案のうち採るものを指示文に入れ、もう一度採点して点の分布を比べる。
