# eval

番組を 20 回作り、検証 4 項目の通過率と「遠く」枠の出現率、DJ の発話の出所を数えます。結果は `docs/eval/<日付>.md` に置きます。

まだ実走していません（`ANTHROPIC_API_KEY` と、デプロイ先または `pnpm dev` が要ります）。実走した日付のファイルが無いうちは、README の数字は空欄のままです。

## 走らせ方

1. Worker を起こす（`pnpm dev`、またはデプロイ先）。`ADMIN_TOKEN` と `ANTHROPIC_API_KEY` を入れておく。
2. 1 日の上限（1 リスナー 10 回）に当たるので、eval のあいだだけ `EPISODE_DAILY_LIMIT=25` のように上げる（ローカルは `.dev.vars`、本番は `wrangler secret put EPISODE_DAILY_LIMIT`）。終わったら戻す。
3. 本人のリスナー ID を `/settings` の末尾の「リスナー ID」の行で確かめる。

```bash
pnpm eval --origin http://127.0.0.1:5173 --listener <listenerId> --runs 20 --out docs/eval/2026-11-0X.md
```

`--origin` は省略すると `$DOCOCA_ORIGIN`、なければ `http://127.0.0.1:5173`。トークンは環境変数 `ADMIN_TOKEN` から読みます（`pnpm eval` は `.dev.vars` を読み、シェルで指定した値が優先されます）。本番に向けるときは `ADMIN_TOKEN="$PROD_ADMIN_TOKEN" pnpm eval --origin https://dococafm.app …` のように渡します。`--token` は実行中にプロセスの引数として見えるので使いません。`--out` を付けないと標準出力に出すだけです。

## 何を数えるか

- **検証 4 項目**: 各回の `report`（原文のまま `verbatim`、出典 `sources`、時事・数字なし `topical`、個人情報・引用なし `pii`）が通った回の数。判定は Worker の決定的な検査で、モデルには聞いていません。
- **作れなかった回**: Worker は検証に落ちた番組を保存せず、作れなければ 503 を返します。保存されたレポートは通ったものだけなので、作れなかった回は全項目の未達として数えます。通過率の分母は試した回数です。
- **定型文だけの回**: DJ の語り（単位の intro / after）が 1 行も入っていない回。単位が検証に通らなかった、または Claude を呼べなかったとき、Worker は手渡しとつなぎの定型文だけで読みます。通ったとしても質が落ちた回として見えるようにします。
- **far 枠**: 「遠く」の枠が 1 つ以上ある回の数。設計上、全回で 100% になるはずです。
- **出所のある DJ 行**: 作り物でない固定文を除く DJ 行のうち、「」『』で括った題名や大文字で始まるラテン文字の固有名を挙げた行を数え、その名がすべて、その回の作品（題名・作者）かお便り（本文・ラジオネーム・土地）に出てくる行の割合。名前を挙げない行は数えません。言い換えによる創作は、この検査では見つかりません。台本に残るのは読まれた文（訳があれば日本語訳）だけなので、英語の原文にしかない名前は出所なしと数えることがあります。「DJ」「YouTube」などの一般語と 1 文字の語は数えません。

落ちた箇所は、行の位置（何枠目の何行目）と理由だけを出力します。DJ の行そのものは書き出しません。
