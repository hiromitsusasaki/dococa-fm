## お便り 1 通あたり

日本語で投稿されたお便りで、日本語と英語の単位（DJ の語り）を両方作る今の設計の場合です。

| 工程 | 呼び出し | トークン・文字数（概算） | 費用 |
|---|---|---|---|
| 判定 | Claude 1 回 | 入 1.0K / 出 0.1K | $0.003 |
| 翻訳（英語） | Claude 1 回 | 入 0.8K / 出 0.3K | $0.005 |
| 単位 日本語（intro と after） | Claude 1〜6 回（通常 1.2 回） | 入 1.8K / 出 0.3K | $0.007 |
| 単位 英語 | 同上 | 同上 | $0.007 |
| 音声 日本語（4 行、約 500 字、再試行込みで ×1.3） | TTS | 650 字 | $0.007 |
| 音声 英語（4 行、約 600 字、×1.3） | TTS | 780 字 | $0.008 |
| 作品のベクトル（作品が新しいとき） | Workers AI 1 回 | | ほぼ $0 |
| **合計** | | | **約 $0.04（約 6 円）/ 通** |

- 聴くだけ（`/stations/:key/next`）は、通常 Claude 0 回・TTS 0 回です。音声は R2 に鍵つきで残り、全員で共有します。聴く人が増えても費用はほとんど増えません。
- 目安: 1 日 100 通で約 $4 / 日（月 1.8 万円ほど）、1 日 10 通で月 2,000 円ほど。固定費は Workers Paid とドメインです。
- Phase 6 で足したもの: 冒頭の一行（「…という曲の紹介です」）の音声は作品と言語ごとに 1 度だけ作り、同じ作品のお便りで共有します。語りの読み（`spoken`）は台本と同じ Claude の呼び出しで返ります。作品の題名と作者の読みは、作品のデータだけを見せる別の呼び出しで、作品ごとに 1 回だけ（かなだけの名前は呼びません）。共有ページ `/letters/:id` の音声は合成せず、作ってある音声だけを返すので、払いません（無い行は本文を見せて進みます）。
- 声の指示文を変えて全部作り直すと、約 1,000 行（1 行 100 字）で 10 万字、約 $1 です。
- 評価: `pnpm eval:units` 40 件で約 41 回、約 $0.15。`pnpm eval` は単位が事前生成されていれば Claude 0 回です。
- 0023 で単位を全部作り直すとき（Phase 6 のデプロイ）は、Claude 約 200 回、TTS 約 1,000 行です。

## 日次の上限（暴走しても青天井にならない歯止め）

どれも呼ぶ前に D1 の数を確かめます。厳密な予約ではなく、同時の要求で少し超えることがあります（`SECURITY.md`）。

| 上限 | 既定 | 守るもの |
|---|---|---|
| `UNIT_DAILY_LIMIT` | 1,000 単位 / 日 | 単位を作る Claude |
| `CLOUD_TTS_GLOBAL_DAILY_LIMIT` | 3,000 行 / 日（本番は 8,000 に設定中。デプロイ後に secret を消すと既定に戻る） | 合成する TTS |
| `LETTER_GLOBAL_DAILY_LIMIT` | 500 通 / 日 | 判定と翻訳 |
| `EPISODE_DAILY_LIMIT` / `EPISODE_GLOBAL_DAILY_LIMIT` | 60 枠 / 人、1,800 枠 / 全体 | 番組の作成（D1 だけ。Claude 0 回） |
| `YOUTUBE_SEARCH_DAILY_LIMIT` | 80 回 / 日 | YouTube の検索 |
| `MAX_SYNTH_PER_KEY` | 1 行（同じ言語・声・本文の鍵）あたり約 6 回 | 指示文を読み上げてしまう行への再試行 |

TTS が 1 日の上限を使い切ると、残りの行はブラウザの音声が読みます。最悪でも TTS は 1 日 3,000 行 × 100 字 × $10 / 100 万字 で約 $3、本番の 8,000 行でも約 $8 です。

## 削れるところ（効果の大きい順）

1. **英語の単位と音声を、英語で聴く人が現れるまで作らない**（遅延生成）。いまは全通に日本語と英語を作るので、英語の聴取が無いかぎり半分が余ります。Cron の `prepareBatch` を「日本語、次に要求された言語だけ」にし、`/stations/:key/next` で英語の単位が無ければその場で作ります（`build.ts` に経路は既にあります）。費用は約 40% 減ります。英語の回を動画に出す前には作っておきます。
2. **判定と翻訳を Haiku 5.5 にする。** 2 回で $0.008 が約 $0.0005 になり、約 20% 減ります。役割別のモデルの鍵 `CLAUDE_MODEL_JUDGE` を足す案で、**まだ実装していません**。判定は 6 つの理由の分類なので Haiku で足りる見込みですが、先に評価（お便りの選別の再判定）で精度を確かめます。
3. **音声の鍵の名前空間を、お便りの本文と DJ の行で分ける。** 今は指示文や台本の方針を変えるたびに、最も長い行（お便りの本文）まで作り直しています。鍵を `tts/v4/dj/…` と `tts/v4/text/…` のように分け、DJ の行だけ版を上げれば、次の調整での作り直しは約 60% 減ります。
4. **見張りの再試行の上限を下げる。** 最悪は 3 回 × 2 言語 × 4 行で 1 通あたり 24 回です。再試行を 2 回で止め、3 回目は翌日の Cron に回すと、障害時の無駄打ちが減ります。
5. 匿名の枠は Claude 0 回なので、費用の問題ではありません（全体の上限を使い切られる問題は `SECURITY.md` の既知の制限）。

## 監視

費用を見る場所は、Anthropic Console・Google Cloud の請求・Cloudflare の 3 つで、アプリの中に合計はありません。

- `/admin/prepare` の応答に当日の合成数と単位の数を返す案があります（どちらも既に数えています）。1 日 1 回 `curl` で見れば足ります。
- Cloud Text-to-Speech の請求アラート（例: 1 日 $10）は、Google Cloud で本人が設定します。
- 音声合成の単価（上の仮定）は、最初の請求で確かめて、この表を直します。
